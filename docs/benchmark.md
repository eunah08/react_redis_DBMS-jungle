# 미니 DBMS 실측

환경: macOS-15.7.7-x86_64-i386-64bit-Mach-O, Intel(R) Core(TM) i5-8259U CPU @ 2.30GHz.
JDK Microsoft 21.0.11, CPU 8개, 최대 JVM heap 536870912 bytes.

- 사용자의 최신 지시에 따라 100만 건 측정을 중단하고 최소 규모로 실행했다.
- 이번 값은 동작 확인용이며 성능 우위를 일반화할 표본 수가 아니다.
- Java 21 `release 21`, `./mvnw package`, 동일 실행 JAR, `-Xms128m -Xmx512m`.
- 각 크기는 새 빈 폴더에 공통 SQL 처리기로 INSERT. 이름 `product_0000001`, price=id.
- 테이블 헤더 44 bytes, 행 44 bytes. B+ 트리 기본 키 최대 64개.
- 파일 적재·재시작 인덱스 재구성·JSON 변환은 조회 측정에서 제외하고 따로 기록.
- 각 고정 조건은 예열 2회 뒤 1회. 실행 순서는 반복마다 교대.
- 무작위는 seed 42의 같은 ID 3개를 세 경로에서 한 번씩 조회.
- 매 조회의 결과와 접근 경로를 확인한다. 인덱스/강제 스캔은 동일 id SQL이다.
- INDEX_ID는 인덱스 위치 직접 읽기, SCAN_ID는 같은 id 강제 스캔(찾으면 종료), SCAN_NAME은 같은 행을 반환하는 이름 조건의 전체 스캔이다.
- 전부 OS 페이지 캐시가 예열된 동일 프로세스의 비교다. JVM GC와 스케줄링 지연도 포함한다.

원본 표본·무작위 ID·측정 시각·환경은 [benchmark_results.json](benchmark_results.json)에 보존한다. JSON/표 출력의 별도 시간은 `target/benchmarks-minimal/*.log`의 `[printReport]` 줄에 남는다.

재현:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 21) # macOS
./mvnw package
sh src/main/java/minidbms/bench/run_benchmarks.sh
```

선형 탐색은 ID 위치에 따라 읽는 양이 다르며, 이름 조건은 전체를 검사한다. 수치는 이 환경과 예열 조건의 결과이며 다른 디스크·JVM·데이터 크기에 그대로 적용하지 않는다.
